SAMS — UX/UI Web System Rebuild Checklist (Student + Supervisor + Admin)

Confirmed approach: this is a **UI/UX reorganization and visual rebuild only**, not a
rewrite of functionality. All existing features, business logic, and behavior stay exactly
as they are — the goal is a clean, organized, easy-to-use interface, styled to match the
mobile app's exact theme (NU navy `#003087`/gold `#ffb81c`, Poppins/Inter, the same
card/badge/button patterns already built for mobile).

Hard rule for this entire rebuild: nothing gets added or removed — no feature, no
page, no field, no button, no file — unless it's explicitly flagged first and approved by
you. If something looks like it should change (a duplicate, dead code, a naming
inconsistency, a broken link, anything), the move is to flag it clearly in this checklist
and wait for approval — never to just make the change while restyling. Every item below
that involves a real decision (not pure visual work) is written as a flag, not an
instruction to act.

Scope: this document covers the **web system only** — Student, Supervisor, and Admin
portals. Mobile app work and paper/documentation tracking are kept in their own separate
files, intentionally not repeated here.

Confirmed sequence: Student → Supervisor → Admin, in that order. Each portal's
rebuild should follow its corresponding Low-Fi wireframe file as the structural starting
point:
- Student → `Student-LowFi-Wireframe.html` (+ `Web-Login-LowFi-Wireframe.html` and
  `Web-Application-LowFi-Wireframe.html` for the login and public application form)
- Supervisor → `Supervisor-LowFi-Wireframe.html`
- Admin → `Admin-LowFi-Wireframe.html`

Scope: 48 PHP files total, several 60–90KB monoliths.
